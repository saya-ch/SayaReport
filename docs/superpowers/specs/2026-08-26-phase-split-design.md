# 指令体系按阶段拆解设计（SayaReport）

> 日期：2026-08-26
> 状态：已获用户批准
> 目标仓库：`saya-ch/SayaReport`

## 背景与问题

Saya 定时任务启动时需通读 `AGENT.md`（392 行），再据其执行五阶段任务。实测观察到的「指令遵循不佳」症状：

1. **每轮行为不一致**：同一要求在不同任务轮次表现波动大，读到的重点漂移
2. **细节丢失**：超链接格式、图片素材、移动端适配等细节要求时做时不做
3. **环境中的插件/skill 不常使用**：虽然 AGENT.md 明确要求，但长文档中易被忽略

根因判断：单一超长 AGENT.md 在每次任务启动时被**整体加载**，注意力被稀释，越靠后的章节（第九章部署、第十章清单）越易被忽略，细节规则在长文中「沉没」。

## 方案

按阶段拆分指令文件，AGENT.md 瘦身为「总纲路由」，每次上下文只加载当前阶段所需指令。

### 文件结构

```
AGENT.md            ← 总纲路由（约 50 行）
PHASE-1.md          ← 初始化与阅读（约 25 行）
PHASE-2.md          ← 信息检索与验证（约 130 行，内容最多）
PHASE-3.md          ← 前端设计与报告素材（约 35 行）
PHASE-4.md          ← 生成 HTML + 独立复审（约 45 行）
PHASE-5.md          ← 部署与收尾（约 55 行）
CHECKLIST.md        ← 进度清单 + 阶段路由（改造）
PROMPT.md           ← 引导词（微调）
```

### 各文件职责映射

| 文件 | 承载内容（对应现有 AGENT.md 章节） | 目标行数 |
|---|---|---|
| **AGENT.md 总纲** | 〇身份、一优先级铁律（压缩）、全程禁止提问、五阶段一句话总览、**阅读机制**、六个人信息、七语气（精简） | ~50 |
| **PHASE-1** | 拉取仓库、通读总纲+CHECKLIST、**首读取消全部打勾**、核对个人信息与求职方向、检查环境（env 注入情况，为阶段五铺垫） | ~25 |
| **PHASE-2** | 二信息检索全部（2.1/2.2/2.3/2.4/2.5）、四五大板块（4.1-4.5）、五质量规范（5.1-5.4） | ~130 |
| **PHASE-3** | 3.2 设计与适配全部、9.3 设计辅助、视觉检查 | ~35 |
| **PHASE-4** | 3.1 输出格式、3.3 页面功能、3.4 独立复审、七语气落地（页眉页脚）、引用阶段二输出格式要求 | ~45 |
| **PHASE-5** | 九部署全部（9.1/9.2/9.3）、README 头图规则、收尾清空清单 | ~55 |

### 关键设计决策

1. **跨阶段约束不重复**：每项规则只写一次，归属其最相关的阶段；其他阶段通过一句话「引用」指向（如阶段四引用阶段二的标注格式），避免多份维护导致的版本漂移。
2. **总纲只留「铁律级」内容**：优先级、禁止提问、阶段路由、身份语气。凡属某阶段的细节一律下沉到对应 PHASE 文件。
3. **CHECKLIST 改造为路由器**：10.1 五阶段清单保留；10.2 打勾规则保留；新增每阶段「下一步读取」指引（完成阶段 N → 打勾 → 读 PHASE-N+1）。
4. **推送保护同步**：9.2 推送范围白名单需加入 `PHASE-*.md`（作为常驻指导文件，禁止任务推送/改动）。
5. **PROMPT.md 微调**：启动后读 AGENT.md 总纲 + CHECKLIST，按路由进入 PHASE-1。

### 阅读机制（写入 AGENT.md 总纲）

- 启动任务：读 AGENT.md 总纲 + CHECKLIST → 读 PHASE-1 → 执行
- 每完成一阶段：打勾 → 读下一阶段 PHASE 文件 → 执行
- 上下文压缩后：重读 AGENT.md 总纲 + 当前阶段 PHASE 文件
- 任务收尾：按 CHECKLIST 10.2 清空全部打勾

### 预期收益

- 每次上下文只加载「总纲 + 当前阶段文件」（约原 1/4 指令量），注意力集中
- 细节规则在「需要用到的那一刻」才进入上下文，降低丢失率
- 插件/skill 要求放在 PHASE-3/4 开头显眼位置，更易触发
- 阶段间通过引用衔接，单一事实源，避免规则漂移

## 实施范围

- 重写 `AGENT.md`（瘦身）
- 新建 `PHASE-1.md` ~ `PHASE-5.md`
- 改造 `CHECKLIST.md`（加阶段路由指引）
- 微调 `PROMPT.md`
- 更新 `9.2 推送保护`（加入 PHASE-*.md 白名单）—— 位于 PHASE-5
- 更新 `README.md` 文件结构表（如需）

## 验收标准

- 各文件行数与目标相符（总纲 ≤60 行）
- 现有 AGENT.md 全部规则可在新体系下找到唯一归属，无遗漏
- 阶段文件之间引用关系清晰，无循环依赖
- CHECKLIST 路由指引明确（阶段 N → 下一阶段文件）
- 推送保护白名单含 PHASE-*.md
- 总纲单独加载即可让 agent 明确「下一步做什么」
